# Генератор шаблонов v1.2 — изолированная лаборатория

Статус: первая интеграция в ветке `feature/character-inventory-ui-v1`. **Не является игровой выдачей предметов.**

## Маршрут

Меню города содержит два независимых пункта:

- `Лаборатория предметов` → `scenes/debug/item_generator_lab.tscn` (legacy, без изменений)
- `Генератор шаблонов v1.2` → `scenes/debug/item_template_generator_v12.tscn`

Второй экран использует:
- `core/items/item_template_generator_v12.gd` — формулы и генерация;
- `data/items/item_generator_v12_rules.json` — снапшот **35 утверждённых архетипов** Project 25 и шести школ магии;
- `tests/items/item_template_generator_v12_runner.gd` — проверки;
- `.github/workflows/item-template-generator-v12.yml` — CI для Godot 4.5.1.

## Реализовано в первом пакете

- Раздельные пресеты и локальное сохранение настроек в `user://boa_template_generator_v12_profile.json`.
- 21 оружейный и 14 броневых архетипов; веса строго дают 100%.
- Fire, Frost, Nature, Lightning, Holy, Dark. Узкое магическое пробитие посоха использует PAR165/166/168/167/170/169 соответственно.
- Канонические PAR для крита PAR033, уворота PAR031, контратаки PAR075, пробития щита PAR072.
- Базовая шкала урона Lv1 2.8, Lv30 30, Lv100 104.2; коэффициенты 1H по семействам; 2H ×1.65; OH ×0.8 для совместимых кинжалов.
- PAR-бюджет 2H 24.75% = 15% MH ×1.65 (не старое экспериментальное 22.5%).
- Ступени редкости white/green/blue/purple, доли бонусных линий, классы броневых архетипов, коэффициент устаревания брони.
- Требования по 2–3 базовым характеристикам и возможная замена бонусной линии на первичную характеристику у перчаток/наручей/поясов.
- Генерация до 500 предметов; фильтры, результаты и CSV с конфигурацией и всеми PAR.

## Ограничения и следующие проверки

1. **Сила атаки** пока `V12_ATTACK_POWER` — *только лабораторное поле*. Не заменять PAR052 (плоский урон), пока не будет согласован канонический ID и преобразование рейтинга.
2. Числовые коэффициенты для некоторых зон брони, посохов, копий, а также пределы DR и экстремумы PAR требуют отдельного сопоставления с полной таблицей баланса и тестовых прогонов. Значения первой лаборатории — рабочие приближения, не сертифицированный боевой баланс.
3. Школьное пробитие генерируется только по школе посоха; общий PAR164 доступен прочим профилям без школы.
4. Кольца, амулеты, щиты и полная специфичная слотовая генерация нуждаются в дополнительных подтверждённых архетипах/формулах. **Не подставлять случайные неверные значения только ради заполнения.**
5. Тесты компиляции/сцены должны пройти GitHub Actions. До успешного CI не считать интеграцию проверенной.
6. Лаборатория не записывает предметы в `ItemRepository`, `Combat Engine` или игровой сейв. CSV предназначен для проверки шаблонов и дальнейшего импорта.

Запуск контрактного теста:

```bash
godot --headless --editor --path . --quit
godot --headless --path . --script res://tests/items/item_template_generator_v12_runner.gd
```


## Аудит после первого успешного CI и Web Preview (2026-11-01)

Внесено в рабочую ветку:

- Зоны брони приведены к утверждённой `МАТРИЦА ДОЛЕЙ БРОНИ V2` из Project 25: голова (шлем 60%, плечи 20%, щит 20%), грудь (плечи 30%, нагрудник 50%, щит 20%), руки (плечи 10%, наручи 30%, перчатки 40%, щит 20%), пояс (нагрудник 20%, пояс 25%, штаны 35%, щит 20%), ноги (штаны 30%, ботинки 50%, щит 20%). Пока в новом генераторе щит не выпускается; по 80% суммарного покрытия зоны без щита проверяет тест.
- Отдельные массивы `core_rolls` и `rolls` (редкость); на Lv20 синий получает 1 CORE, Lv30 все редкости 1 CORE, Lv60+ — 2 CORE. Физические базовые параметры не являются CORE.
- Повторные PAR в бонусах редкости допустимы; суммы одинаковых PAR учитываются, а замена случайной линии основной характеристикой не стирает другие экземпляры PAR.
- Результаты и CSV разделяют CORE и бонусные линии редкости.
- Контрактные тесты расширены на матрицу зон, уровни, CORE/редкости и привязку школьного пробития.

**Новая сборка после исправлений требует повторного зелёного CI.** Ранее полученный Success относится к более раннему состоянию ветки.

Следующие ограничения для аудита с полным балансом:

- Общая предельная стоимость PAR, DR (кривые 30/85,1 и другие), стоимость экстремумов и единицы некоторых бонусов ещё не перенесены в конечный числовой расчёт.
- Проценты внебоевой регенерации в Project 25 и действующий flat PAR013 (ед./10 сек) — неэквивалентные единицы; нужна корректная настройка/конверсия.
- Отдельные шаблоны щитов, украшений и магического OH остаются за рамками текущего стартового набора 35 архетипов.
- Генерация одиночных строк `CORE` для разных цветов пока создаёт самостоятельные экземпляры, а не связанную группу вариаций от одного фиксированного белого шаблона.


## Числовая калибровка DR и фильтров (пакет после CI)

- Функция `ItemTemplateGeneratorV12.diminishing(raw_pct, category)` дословно повторяет формулу `Генератор v1.2!B13` из Project 25: `t+(c-t)×x/(1+x^s)^(1/s)`, где `x=(raw-t)/(c-t)`.
- Категории: броня (30/85,1/1,5), уворот (15/80/1,5), крит (20/100/1,5), сила крита (50/250/1), снижение урона (5/35/1), сопротивление магии (30/85,1/1,5), блок (20/75/1,5), сила атаки (75/250/1).
- До DR сырой рейтинг брони переводится в проценты как `rating/(2×K(level))`; `K(level)=1+3×(level−1)/99`.
- Рейтинг крит/уворот/антиуворот: 100 рейтинга = 20% на Lv1 и 4% на Lv100, линейно по уровню.
- Генератор сохраняет **сырые PAR**. Выведенные в карточке и CSV поля `preview` — **диагностический просмотр** до/после DR, а не новый источник параметров или подмена Combat Engine. Для PAR со шкалой рейтинга, пока не зафиксированной в Project 25, процентную оценку не показываем.
- Кандидаты теперь фильтруются по доступности редкости **до** случайной выборки: 100 фиолетовых Lv30–40 дают 100 вариантов Lv40, а не случайно меньше ста.
- При выбранной школе генерируются только посохи этой школы; при выбранном броневом слоте — только соответствующая броня.
- Автотесты содержат эталоны: броня 40%→39,5156%; 100%→68,7078%; 100 рейтинга на Lv1→20%, Lv100→4%; пороги редкости и фильтры.

**Важно:** точные численные величины бонусов отдельных PAR и базовый урон посохов пока остаются задачами финального аудита. Приблизительные величины первого генератора не считать утверждённым балансом.


## Калибровка числовых PAR — контроль Lv10/30/60/100 (2026-11-01)

Источник: `Project 25 → Генератор v1.2`, реестр правил K:N.
Проверка выполняется отдельно от Combat Engine и от старого генератора.

**Бюджет 14 слотов:** сумма = 100%. Эталонный вес одного слота = 100/14%.
В коде `nominal_affix(logical, level, slot, quality)` множитель слота
`slot_weight / (100/14)`. Реальные бонусы получают случайное отклонение
±5% при окончательном округлении, минимум +1.

**Подтверждённые уровневые эталоны для одной PAR-доли в условном среднем слоте, белое качество:**

| Item Level | HP | Mana |
| ---: | ---: | ---: |
| 10 | 10.119 | 5.060 |
| 30 | 30.357 | 15.180 |
| 60 | 60.714 | 30.360 |
| 100 | 101.190 | 50.600 |

Для зелёного качества ×1.1, синего ×1.25, фиолетового ×1.5.
Это абсолютные рейтинги одного бонусного PAR, не величина итогового HP персонажа.

**Профильные цели сборок**, а не утверждённая отдельная шкала каждого PAR:
- Физическая сила атаки: Lv10 +50%, Lv100 +150% **до DR**.
- Сила заклинаний: Lv20 ~200, Lv100 ~2000 рейтинга.
- Для распределения эталона по предметам используется модель **14 слотов × 2 PAR × эпик 1.5**.
- Промежуточные значения между опорными уровнями рассчитываются линейной интерполяцией **только в лаборатории**. Шкалу нельзя автоматически переносить в бой.
- Сила атаки остаётся локальной меткой `V12_ATTACK_POWER`; канонический PAR для этого параметра ещё не утверждён.

**Бюджеты и качество:**
- Числовые величины не делятся на число фактически доступных строк CORE/редкости.
- Неоткрытые доли стоимости не перераспределяются.
- Для каждой CORE/rarity строки добавлено поле `calibration`: `PROJECT25_ANCHOR`, `PROJECT25_TARGET_INTERPOLATED` или `PROVISIONAL_EXTREMUM`.
- Все другие PAR, включая крит/уворот/пробитие/резисты и конверсию регенерации, **пока используют предварительный числовой масштаб**. Их окончательные экстремумы ещё требуют согласования.

**Контрольные автотесты** сверяют уровни 10, 30, 60 и 100, 14 слотов =100%, бонусы HP/Mana, ×1.5 фиолетового, целевые значения силы атаки/заклинаний и статус калибровки. Интеграция не читает расчётный сервис персонажа; лишь локальный JSON реестра PAR.

**Следующий блок:** полный каталог экстремумов PAR и единиц рейтинга, затем реализация утверждённого бюджета защиты/атаки внутри PAR-слотов и полноценные шаблоны щитов/украшений. Есть конфликт между историческими правилами `Генерация предметов — правила` и новыми `Генератор v1.2` (порог синего качества, коэффициенты урона и OH, бюджет); для v1.2 эти числа должны быть сверены, а не смешаны.


## Требования атрибутов · проверка с Project 25

Независимая лаборатория использует `B(L)=18+2×(L−1)`.
Каждая из N профильных характеристик должна иметь
`round_half_up(B(L)×K/N×F(L))`, итог округляется один раз.

- Lv1–10: `F=0`, список требований пустой.
- Lv11–15: `F=0,25; 0,3125; 0,375; 0,4375; 0,50`.
- Lv16–19: `F=0,60; 0,70; 0,80; 0,90`.
- Lv20+: `F=1`.
- `K=0,70` для высоких требований; `K=0,40` для утверждённого архетипа посоха поддержки. Остальные профили пока используют высокий порог до отдельного утверждения числового значения K.
- При трёх характеристиках N=3, а не N=2 с дополнительной платой.
- При отсутствии требований на Lv10 случайный бонус базового атрибута использует профиль архетипа, а не пустой словарь требований.

Контроль для двух атрибутов и K=0,70:
Lv10 = нет требований; Lv11 = 3/3; Lv15 = 8/8;
Lv20 = 20/20; Lv30 = 27/27; Lv100 = 76/76.
Для трёх атрибутов Lv30 = 18/18/18.
Для посоха поддержки Lv30 при K=0,40 = 15/15.
Добавлены соответствующие автотесты. Combat Engine и старая лаборатория не изменяются.

## Исправление архитектуры v1.2 — 2026-11-01

В v1.2 **нет** отдельного бонусного механизма компенсации брони. Код, добавлявший дополнительную линию PAR в зависимости от класса брони, откатан; удалены соответствующие строки UI, CSV и тесты. Архетипные соотношения 80/20, 55/45, 20/80 и т. д. обозначают **бюджеты защитных и атакующих PAR**, а не новый источник бонусов. Базовая броня рассчитывается отдельно; число PAR-слотов определяется правилами CORE и редкости.

Распределение бюджета защиты/атаки и фактическая стоимость PAR пока ещё требуют числовой калибровки. Формула `_base_armour` проверена по контрольным числам вкладки `Генератор v1.2`; менять её коэффициенты без нового подтверждения нельзя.


## Единственный нормативный источник для следующего этапа

Основной нормативный источник: Project 25 → **«Генератор v1.2»** (`gid=1152411451`).
Другие вкладки, включая старые правила предметов и отдельные таблицы архетипов, используются только после проверки совместимости с этой вкладкой. Старые и новые формулы не смешиваются автоматически.

**Проверенные значения базовой брони (белый Lv1):**
- 80/20 тяжёлый шлем: PAR100=48; плечи по голове=16.
- 65/35 тяжёлый шлем: PAR100=39; плечи по голове=13.
- 50/50 средний шлем: PAR100=30; плечи по голове=10.
- 20/80 лёгкий шлем: PAR100=12; плечи по голове=4.

Их расчёт: `defence_budget × zone_fraction × K(item_level) × rarity_factor`,
`K(L)=1+3×(L−1)/99`. Предыдущая формула арифметически эквивалентна этому выражению.
Профиль является отношением бюджета **защита/атака**, не вероятностью выпадения PAR. Код проверяет сумму частей =100%; для брони формируется `budget_split` в карточке и CSV, **не добавляя** ни одной строки PAR.
Новые тесты закрепляют все четыре профиля на Lv1/Lv100 и множитель качества ×1,5.

**Направления PAR, прямо указанные в текущей вкладке:**
- Защитные: HP, уменьшение урона, физические и магические сопротивления.
- Атакующие: крит, сила крита, сила атаки, сила магии, пробивание.
- Смешанный: уворот 75% защитного / 25% атакующего бюджета.
- Прочие спорные категории пока имеют `UNCLASSIFIED` в `budget_direction`; новые множители к их численным значениям не применяются.

**Открытое противоречие внутри v1.2:** в таблице DR (E:I) сила атаки указана с порогом DR 75 / MAX 250 / smooth 1, но текст «БЕЗ DR» ниже включает «силу атаки и силу заклинаний». До уточнения не применять новый DR к силе атаки. Численные экстремумы остальных бонусов остаются предварительными.

# Генератор шаблонов v1.2 — изолированная лаборатория

Статус: первая интеграция в ветке `feature/character-inventory-ui-v1`. **Не является игровой выдачей предметов.**

## Маршрут

Меню города содержит два независимых пункта:

- `Лаборатория предметов` → `scenes/debug/item_generator_lab.tscn` (legacy, без изменений)
- `Генератор шаблонов v1.2` → `scenes/debug/item_template_generator_v12.tscn`

Второй экран использует:
- `core/items/item_template_generator_v12.gd` — формулы и генерация;
- `data/items/item_generator_v12_rules.json` — снапшот **35 утверждённых архетипов** Project 25 и шести школ магии;
- `tests/items/item_template_generator_v12_runner.gd` — проверки;
- `.github/workflows/item-template-generator-v12.yml` — CI для Godot 4.5.1.

## Реализовано в первом пакете

- Раздельные пресеты и локальное сохранение настроек в `user://boa_template_generator_v12_profile.json`.
- 21 оружейный и 14 броневых архетипов; веса строго дают 100%.
- Fire, Frost, Nature, Lightning, Holy, Dark. Узкое магическое пробитие посоха использует PAR165/166/168/167/170/169 соответственно.
- Канонические PAR для крита PAR033, уворота PAR031, контратаки PAR075, пробития щита PAR072.
- Базовая шкала урона Lv1 2.8, Lv30 30, Lv100 104.2; коэффициенты 1H по семействам; 2H ×1.65; OH ×0.8 для совместимых кинжалов.
- PAR-бюджет 2H 24.75% = 15% MH ×1.65 (не старое экспериментальное 22.5%).
- Ступени редкости white/green/blue/purple, доли бонусных линий, классы броневых архетипов, коэффициент устаревания брони.
- Требования по 2–3 базовым характеристикам и возможная замена бонусной линии на первичную характеристику у перчаток/наручей/поясов.
- Генерация до 500 предметов; фильтры, результаты и CSV с конфигурацией и всеми PAR.

## Ограничения и следующие проверки

1. **Сила атаки** пока `V12_ATTACK_POWER` — *только лабораторное поле*. Не заменять PAR052 (плоский урон), пока не будет согласован канонический ID и преобразование рейтинга.
2. Числовые коэффициенты для некоторых зон брони, посохов, копий, а также пределы DR и экстремумы PAR требуют отдельного сопоставления с полной таблицей баланса и тестовых прогонов. Значения первой лаборатории — рабочие приближения, не сертифицированный боевой баланс.
3. Школьное пробитие генерируется только по школе посоха; общий PAR164 доступен прочим профилям без школы.
4. Кольца, амулеты, щиты и полная специфичная слотовая генерация нуждаются в дополнительных подтверждённых архетипах/формулах. **Не подставлять случайные неверные значения только ради заполнения.**
5. Тесты компиляции/сцены должны пройти GitHub Actions. До успешного CI не считать интеграцию проверенной.
6. Лаборатория не записывает предметы в `ItemRepository`, `Combat Engine` или игровой сейв. CSV предназначен для проверки шаблонов и дальнейшего импорта.

Запуск контрактного теста:

```bash
godot --headless --editor --path . --quit
godot --headless --path . --script res://tests/items/item_template_generator_v12_runner.gd
```


## Аудит после первого успешного CI и Web Preview (2026-11-01)

Внесено в рабочую ветку:

- Зоны брони приведены к утверждённой `МАТРИЦА ДОЛЕЙ БРОНИ V2` из Project 25: голова (шлем 60%, плечи 20%, щит 20%), грудь (плечи 30%, нагрудник 50%, щит 20%), руки (плечи 10%, наручи 30%, перчатки 40%, щит 20%), пояс (нагрудник 20%, пояс 25%, штаны 35%, щит 20%), ноги (штаны 30%, ботинки 50%, щит 20%). Пока в новом генераторе щит не выпускается; по 80% суммарного покрытия зоны без щита проверяет тест.
- Отдельные массивы `core_rolls` и `rolls` (редкость); на Lv20 синий получает 1 CORE, Lv30 все редкости 1 CORE, Lv60+ — 2 CORE. Физические базовые параметры не являются CORE.
- Повторные PAR в бонусах редкости допустимы; суммы одинаковых PAR учитываются, а замена случайной линии основной характеристикой не стирает другие экземпляры PAR.
- Результаты и CSV разделяют CORE и бонусные линии редкости.
- Контрактные тесты расширены на матрицу зон, уровни, CORE/редкости и привязку школьного пробития.

**Новая сборка после исправлений требует повторного зелёного CI.** Ранее полученный Success относится к более раннему состоянию ветки.

Следующие ограничения для аудита с полным балансом:

- Общая предельная стоимость PAR, DR (кривые 30/85,1 и другие), стоимость экстремумов и единицы некоторых бонусов ещё не перенесены в конечный числовой расчёт.
- Проценты внебоевой регенерации в Project 25 и действующий flat PAR013 (ед./10 сек) — неэквивалентные единицы; нужна корректная настройка/конверсия.
- Отдельные шаблоны щитов, украшений и магического OH остаются за рамками текущего стартового набора 35 архетипов.
- Генерация одиночных строк `CORE` для разных цветов пока создаёт самостоятельные экземпляры, а не связанную группу вариаций от одного фиксированного белого шаблона.


## Числовая калибровка DR и фильтров (пакет после CI)

- Функция `ItemTemplateGeneratorV12.diminishing(raw_pct, category)` дословно повторяет формулу `Генератор v1.2!B13` из Project 25: `t+(c-t)×x/(1+x^s)^(1/s)`, где `x=(raw-t)/(c-t)`.
- Категории: броня (30/85,1/1,5), уворот (15/80/1,5), крит (20/100/1,5), сила крита (50/250/1), снижение урона (5/35/1), сопротивление магии (30/85,1/1,5), блок (20/75/1,5), сила атаки (75/250/1).
- До DR сырой рейтинг брони переводится в проценты как `rating/(2×K(level))`; `K(level)=1+3×(level−1)/99`.
- Рейтинг крит/уворот/антиуворот: 100 рейтинга = 20% на Lv1 и 4% на Lv100, линейно по уровню.
- Генератор сохраняет **сырые PAR**. Выведенные в карточке и CSV поля `preview` — **диагностический просмотр** до/после DR, а не новый источник параметров или подмена Combat Engine. Для PAR со шкалой рейтинга, пока не зафиксированной в Project 25, процентную оценку не показываем.
- Кандидаты теперь фильтруются по доступности редкости **до** случайной выборки: 100 фиолетовых Lv30–40 дают 100 вариантов Lv40, а не случайно меньше ста.
- При выбранной школе генерируются только посохи этой школы; при выбранном броневом слоте — только соответствующая броня.
- Автотесты содержат эталоны: броня 40%→39,5156%; 100%→68,7078%; 100 рейтинга на Lv1→20%, Lv100→4%; пороги редкости и фильтры.

**Важно:** точные численные величины бонусов отдельных PAR, компенсации ткани/кожи и базовый урон посохов пока остаются задачами финального аудита. Приблизительные величины первого генератора не считать утверждённым балансом.

## 1. Предварительные границы ответственности

| Модуль | Собственные определения/значения | Основной существующий источник | Разрешённые ссылки/адаптеры | Не его ответственность |
|---|---|---|---|---|
| PAR | ID, смысл, единицы, формулы первичных/производных параметров, рейтинги/DR | `data/parameters/par_registry.json`; `data/character/primary_stat_effects.json`; `data/balance/rating_matrix.json`; `core/parameters/*` | ITEM хранит `PARxxx: value`; CHAR/NPC собирают итог | Конкретная сила предмета, собственные данные ABI/EFF |
| ITEM / архетипы | Шаблон, роллы, редкость, индивидуальная величина PAR, слот, требования, предоставляемые ABI ID | `data/items/item_generator_v12_rules.json`; `core/items/item_template_generator_v12.gd`; `item_v12_instance_factory.gd` | `PARxxx`, `ABIxxx` | Реализация эффекта/способности, длительность EFF |
| ABI | Способность, AP/мана/CD, условия и цель, какие EFF вызываются и с какими данными применения | `data/abilities/catalog.json`; `core/abilities/*` | `EFFxxx`, COMBAT action API | Базовая длительность/стакинг EFF, правила PAR, собственный боевой движок |
| EFF | ID, длительность или правило её вычисления, максимальные стаки, числовая сила, статус/полярность, жизненный цикл | `data/effects/catalog.json`; `core/effects/*`; текущий event runtime в `core/combat/combat_engine.gd` | PAR ключи для модификаторов; вызов из ABI/ITEM | Владеющие способностью AP/CD; повторные числа в COMBAT |
| CHAR | Прогрессия/оборудование, текущие HP/мана, сохранение, подготовка снимка для боя | `core/character/*` | PAR, ITEM, ABI IDs | Повторная математика EFF или Combat |
| NPC | Тип/шаблон, уровень, исходные параметры, сила/событийный коэффициент, AI/назначенные ABI | `data/npc/starting_region_npcs.json`; `core/npc/*` | PAR, ABI; Combatant adapter | Особый параллельный расчёт рейтингов и бой |

| TALENT (будущее) | Не создаётся сейчас; пример проверки расширяемости | — | В будущем ссылочные модификаторы PAR/ABI/EFF | Не должен требовать копирования EFF или создания второго Combat Engine |

Важно: `ITEM -> PAR006: +5` корректен. ID и величина конкретного бонуса принадлежат предмету. Значение «что такое PAR006» и его преобразование принадлежат PAR. Runtime checkpoint может хранить **снимок** EFF для возобновления уже начатого боя; этот снимок не является альтернативным каталогом баланса.

## 3. Уже корректные границы

- ITEM экземпляр хранит `par_bonuses: {"PAR006":5}`: значение относится к вещи; эффект END→MaxHP определён PAR.
- ABI и EFF имеют отдельные JSON каталоги; `AbilityCatalog` и `EffectCatalog` уже существуют.
- Единая RatingMatrix конвертирует рейтинг → %; нет основания создавать вторую систему рейтингов.
- `ResourceRegenerationRules` — одна настройка базового восстановления, используемая вне боя и в начале раунда.
- `CharacterCombatBuilder` собирает снимок PAR → Combatant; Combat Engine не должен пересоздавать PAR.
- UI должен использовать готовые snapshots; точные зависимости экранов ещё требуют отдельного аудита.
- Сохранённые EFF записи — runtime state; не применять новый текущий баланс задним числом к уже начатому раунду без отдельного решения.
